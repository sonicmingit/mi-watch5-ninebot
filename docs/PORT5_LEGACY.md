# port5：我的车辆标题、启动标志和退出登录

用户要求修复“我的车辆”页字体裁切，恢复启动页原黑色九号标志，并新增手动退出登录。沿用 `sonic-dev-小米手表开发` 技能和原签名，不更换包名，不改手机官方 App。

## 实现

- `activity_device_list` 中两个标题容器原固定 28dp；改为自适应高度、最小 36dp。返回标题内部清除上下 margin，字号 16sp、保留字体上下留白。先前 port4 只修了详情页，此次实机复现并修复列表页“我的车辆”底部裁字。
- 桌面继续用 port4 的蓝紫圆形九号图标。应用内启动资源恢复原 `nb_logo_background.png`，Android 12+ 系统启动主题另指定原图并加 20% 安全留白，避免默认桌面图标外的白圈以及系统圆形蒙版裁字。
- 新增 `AccountUi.java`，作为私有 ContentProvider 注册 Activity 生命周期回调，在详情页滚动区域末尾和车辆列表页页脚加入“退出登录”。确认页采用圆屏留边，支持取消、系统返回。
- 点击“确认退出”后同步提交删除 `com.ninebot.ninebot` 偏好中的 `uid`、`token`，提交失败不退出；成功后关闭 Activity 并结束本进程，清除原 SDK 内存中的账号状态。界面明确说明退出会关闭应用。重新打开后走原手机授权流程。保留协议确认、设备信息等其他偏好；这是本机退出，不撤销服务端令牌。
- 原封装 `classes.dex` 与 port3 完全一致；新增 `classes2.dex` 仅提供本地 UI 与清理操作，不含网络或控车代码。未新增导出组件或权限。

## 手动重新授权

1. 手表九号车辆页下滑，点“退出登录 → 确认退出”。应用关闭后，先打开手表授权助手。
2. 手机和手表在同一 Wi-Fi；手机官方九号已登录。手表授权助手“开始配对”，手机助手输入手表显示的地址并连接。
3. 核对两端配对码并确认。通过助手打开手机官方九号，再打开手表九号。
4. 显示车辆后可结束授权连接。日常由手表自身联网，令牌失效时再授权。

构建入口：`build_port5.py`；清单增量：`account_manifest.py`；系统启动主题：`splash_theme.py`。测试文件与日志均在规定目录，没有外传凭据。

## 21:58 用户手动配对排错

手机填写 10.0.0.5:37499，屏幕报 SSLHandshakeException。ADB connect 验证 37499 是当前无线调试端口，不能作为授权 TLS 地址。手机局域网正常。打开手表授权助手并点开始配对，手机地址纠正为 10.0.0.5:38766。用户同期操作，两端于 21:57:49 记录 requestInitInfo 往返，手机发出及手表收到 token_present=true、uid_present=true。只确认授权消息传输，不把它单独视为重新授权后车辆接口成功；用户随后处于退出确认页面，未代点确认。未改 APK。后续说明必须强调地址来自授权助手，而非无线调试设置。
